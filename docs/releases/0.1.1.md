# Leaflogue 0.1.1 — reader and optional book-file sync

Planned milestone, not released or implemented. This follows the 0.1.0
cross-platform beta and local MCP server. No release date is committed.

## User experience

1. Attach a DRM-free EPUB to an existing book, or add a book from its file.
2. Keep the file on this device by default; explicitly choose whether to sync it.
3. Open **Read** from the book page, with matched highlights visible in context.
4. Select text to highlight, add a note, define a word offline, or use the
   existing optional AI explanation flow.
5. See reader-created highlights immediately in the normal book page, passage
   search, tags, and threads. Edits and deletions in either view affect the same
   annotation record rather than creating a second reader-only library.
6. Choose **Read in context** on an anchored passage to return to its location.
7. Resume reading offline and, when sync is enabled, on another installation
   that has access to the book file.

## Implementation order within 0.1.1

### Local EPUB reader

- [ ] Add attachment identity and integrity metadata, preserving the original
  file and associating each annotation anchor with the exact file edition.
- [ ] Provide table of contents, book search, bookmarks, saved reading position,
  typography controls, themes, and keyboard-accessible navigation and selection.
- [ ] Store a format-specific text-range anchor plus quotation/context so
  font changes and window resizing do not move a highlight to different text.
- [ ] Use the existing highlight and note mutations for create, edit, and delete;
  retain parity across local SQLite, PostgreSQL, and Convex.
- [ ] Integrate the dictionary and optional AI through existing permission and
  disclosure flows. Keep book content isolated from application privileges.

### Optional file sync and reading position

- [ ] Keep reading-data sync and file sync separate. Connecting a sync database
  must never upload books automatically; require explicit per-book or bulk opt-in.
- [ ] Offer download-for-offline and remove-local-download actions. Removing a
  cached file must retain the logical book, passages, notes, and remote copy.
- [ ] Define remote storage, access controls, integrity checks, transfer limits,
  resumable downloads/uploads, and understandable failure/retry states.
- [ ] Synchronize reading position without silently overwriting a newer position
  with stale offline state; let the user recover from conflicting device progress.
- [ ] Document whether backups contain book bytes or only library metadata,
  and verify restore against that documented behaviour.

### Existing imported highlights

- [ ] Attempt matching against the attached edition using source locations,
  quoted text, and surrounding context where available.
- [ ] Place confident matches, ask the user to confirm ambiguous matches, and
  preserve unmatched passages with a clear explanation. Never silently guess.
- [ ] Handle repeated quotations, punctuation/whitespace differences, and
  replacement editions without corrupting source text or creating duplicates.

## Acceptance before release

- [ ] Import/attach an EPUB, highlight and annotate while offline, restart,
  and reopen at the correct position with the same highlights.
- [ ] Edit/delete from both reader and library views; prove both update the same
  records and connected devices converge without duplicate annotations.
- [ ] Demonstrate two-device opt-in file transfer, interrupted transfer recovery,
  offline download, local eviction, and reading-position reconciliation.
- [ ] Verify font/size/theme/viewport changes preserve anchors and selection.
- [ ] Exercise confident, ambiguous, missing, and changed-edition matches.
- [ ] Validate backup/restore and original-file integrity with book attachments.
- [ ] Test keyboard and screen-reader workflows on supported desktop systems,
  and isolate malformed or active book content from application capabilities.
- [ ] Update user guides and screenshots with the final supported workflow.

## Outside this milestone

PDF reading follows EPUB; scanned PDFs and OCR need their own scope. Other
ebook formats, DRM-protected books, format conversion, and writing annotations
back to Kindle/Kobo or other external readers are not promised for 0.1.1.
Browser reading is a separate follow-up; it requires explicitly synced files
and authenticated access, not access to a desktop's local file paths.
